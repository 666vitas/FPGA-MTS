# 开源锁定方案横向对比

## 1. 比较范围

| 项目 | 本地形态 | 核心定位 |
|---|---|---|
| FPGA-MTS | active SystemVerilog + Python | MTS-specific L1 realtime ERROR crossing P-only |
| Linien 2.1.0 | 完整源码 | spectroscopy autolock application |
| PyRPL | Windows PyInstaller binary | generic FPGA instrument + model-based lockbox |
| redpid | 完整源码快照 | digital servo/gateware substrate |
| RedPitaya-FPGA | 完整源码快照 | official hardware/interface/examples |
| FPGABuilder 0.2.0 | 完整源码快照 | alpha build framework |

## 3. acquisition 策略比较

```text
FPGA-MTS:
historical aligned capture
-> operator-selected feature/crossing
-> ARM_VALIDATE
-> next matching realtime ERROR crossing is only recorded
-> ARM_ACTIVE
-> actual OUT2 captured -> Kp ramp -> supervisor

Linien simple:
reference spectrum
-> CPU correlation estimates shift/target sweep count
-> FPGA waits target sweep position (up sweep)
-> hold sweep + enable PID

Linien robust:
multiple spectra
-> server compiles peak sequence
-> FPGA matches real-time peak signs/heights/separations
-> hold sweep + enable PID

PyRPL lockbox:
physical model + inputs/outputs
-> configured stages/setpoints/gains
-> stage-by-stage lock and saturation monitoring
```

FPGA-MTS 当前方案在“已知目标 crossing 的确定性切换”上更贴合首个 P-only；
Linien 在“跨扫描识别同一谱线”上更强；PyRPL 在“多 actuator model/stages”
上更强，但都假定它们拥有或可配置全部相关执行器。

## 4. 开源功能推荐分类

| 项目/功能 | 分类 | 原因 | 推荐阶段 |
|---|---|---|---|
| Official v0.94 shell/XDC | DIRECTLY REUSABLE | 已复用并保持最小差异 | 现在 |
| Linien client/server/FPGA ownership | CONCEPTUALLY REUSABLE | 与目标架构一致 | 现在作为设计原则 |
| Linien simple correlation | CONCEPTUALLY REUSABLE | 可验证 line identity；不参与首个 trigger | H4 后 |
| Linien robust autolock | REQUIRES ARCHITECTURE CHANGE | Migen/CSR/scope/instruction pipeline | FUTURE ONLY |
| PyRPL OutputSignal/Stage model | CONCEPTUALLY REUSABLE | 可描述 actuator/limits/setpoint | P2/P3 |
| PyRPL PID/IQ binary | REQUIRES ARCHITECTURE CHANGE | 完整 FPGA image/CSR dependency | 不引入 |
| redpid relock | DANGEROUS UNDER CURRENT HYBRID LOOP | expanding sweep + unknown D2 loop | 禁止当前 |
| official average decimator | CONCEPTUALLY REUSABLE | 有 noise/alias 优点但改变 capture semantics | 真实问题出现后 |
| FPGABuilder | NOT APPLICABLE NOW | build migration 不服务 P-only Gate | H4 后再议 |

## 5. 混合 D2-125 结论

```text
                 +--> D2-125 controller --> current actuator --+
MTS ERROR -------+                                              +--> laser frequency
                 +--> FPGA P controller ----> PZT actuator -----+
```

所有开源双执行器方案的共同隐含条件是：系统能设置、enable/disable、reset、
监控两路 controller。当前外部 D2-125 不满足，因此：

- 不能把 Linien slow integrator 或 PyRPL multi-output model 直接套用；
- 不能在 D2 状态 `UNKNOWN` 时把 FPGA supervisor 的 `P_LOCKED` 当成
  系统锁定；
- first P-only Gate 必须把 D2 状态作为强制人工确认输入；
- 双环带宽/职责分离只能由测量建立，不能由开源项目的默认参数推断。

## 6. 总结

当前最合理的组合不是“选一个开源项目替换 FPGA-MTS”，而是：

```text
保留 official Red Pitaya shell
+ 保留现有 L1 deterministic crossing/bias/controller
+ 借鉴 Linien 的职责边界与未来 line identity
+ 借鉴 PyRPL 的显式 actuator metadata
+ 不引入当前无关的 robust/relock/PI/build framework
```
