# 上位机选谱线到锁定的最小闭环方案

## 1. 目标工作流

```text
SAFE
-> 用户确认真实接线和 D2-125 状态
-> START SCAN
-> aligned capture(PD, ERROR, OUT2)
-> 用户选择目标 PD feature（也允许工程诊断直接点 ERROR）
-> GUI 在同一 capture 解析附近 ERROR crossing
-> 显示 scan direction / ERROR direction / OUT2 / slope / noise
-> 用户确认 target
-> ARM VALIDATE
-> FPGA 在下一次匹配事件只记录，不切换
-> GUI 对比 selected vs validated event
-> 用户批准 ARM ACTIVE
-> FPGA 原子捕获实际 OUT2
-> ACQUIRING，Kp effective 从 0 soft-start
-> 检查谱峰、error、correction、saturation 与 D2 状态
-> FPGA supervisor P_LOCKED 或 FAILED/FAULT -> SAFE
-> 用户批准继续观察 sustained P-only
```

当前 L1 与任务说明中旧的“P_LOCK_KP0 后再手动 APPLY P”略有差异：
active RTL 已支持预批准 Kp target 并在 FPGA 内 soft-start。为了保持用户
批准边界，第一次 ACTIVE 可以明确请求 `Kp=0`；只有该硬件 Gate 通过后，
下一轮才由用户请求最小非零 target。legacy `APPLY P` 仅作工程诊断。

## 2. 目标交互定义

最合理的 operator interaction：

1. GUI 显示同一 aligned capture 的 PD、ERROR、OUT2。
2. 默认要求用户在 PD 上选“谱线身份区域”，而不是把鼠标像素当 lock point。
3. GUI 在该区域内搜索 ERROR crossing，进行线性插值并计算：
   `scan_direction`、`error_crossing_direction`、slope、local noise、
   guard center/window。
4. rising/falling 目标分开显示和保存；一个方向的 target 不得用于另一个方向。
5. target 绑定 `capture_id + scan_generation + config_generation`。
6. 改变 scan center/amplitude/frequency、重新 SCAN 或新 capture 后旧 target
   自动失效。
7. VALIDATE 必须先于 ACTIVE；其 event generation/directions/OUT2/error
   不匹配时不允许 ACTIVE。

当前 GUI 已做到 click CH1/CH3、ERROR crossing 插值、方向、generation 与
诊断显示；真正缺少的是统一 `scan_generation` 和 D2 人工确认 gate。

## 3. VALIDATE 对比判据

GUI 应同时显示：

| 字段 | selected capture | validated event | PASS |
|---|---:|---:|---|
| capture/config generation | N | event generation | generation matches current target |
| scan direction | rising/falling | FPGA event direction | equal |
| ERROR direction | N→P/P→N | FPGA event direction | equal |
| OUT2 | nominal guard center | actual event OUT2 | within approved guard |
| ERROR | interpolated crossing | actual raw ERROR | within H/noise expectation |
| lock_error | near setpoint | event lock_error | H/N detector-consistent |
| timestamp | host capture time | FPGA cycle timestamp | present/coherent |

VALIDATE 只证明“下一次匹配事件可以重复识别”，不证明 lock、bumpless 或
plant stability。

## 4. scan-to-lock 方案比较

| 方案 | 确定性 | hysteresis/方向 | D2 loop 影响 | jump 风险 | 当前 Gate |
|---|---|---|---|---|---|
| A. host/Linux 轮询 OUT2 后写 capture | 低 | direction/crossing 易错 | 延迟期间 D2 可移动 line | 高/不可重复 | legacy only |
| B. FPGA direction+guard+ERROR crossing | 高 | 显式区分 | D2 仍会改变 crossing，但 trigger 本身确定 | actual bias 可降 jump | 当前主路径 |
| C. HOLD selected count | 中 | dynamic→static hysteresis 大 | D2 可继续拉 current | selected count 不等于静态点 | 诊断回退 |
| D. controlled approach | 低速确定 | 可测 slope 后小步 | D2 闭环会改变有效 slope | slew小但非实时 | 仅有硬件证据需要时 |
| E. Linien-style autolock | robust 可高 | 强 line identity | 假定统一 controller ownership | 需新 gateware | FUTURE ONLY |
| F. VALIDATE→ACTIVE | 高且可审计 | 先验证同方向同 crossing | 能暴露 D2 导致的 event drift | 最低 | 当前推荐 |

所有 ACTIVE 方案都需要先明确 Kp target。第一轮用 Kp=0；非零 Kp 不应在
D2 状态 UNKNOWN 时启用。

## 5. P-only 数学与时序

当前实现：

```text
lock_error = laser_error - error_setpoint
signed_error = polarity ? -lock_error : lock_error
p_term = (signed_error * kp_effective) >>> 8
correction = clamp(p_term, +/- correction_limit)
target = clamp(lock_bias + correction, +/- absolute_limit)
OUT2 next = slew(current OUT2, target, slew_limit) on servo tick
```

证据：

- setpoint corrector 与 controller wiring：
  `../v0.94/rtl/red_pitaya_top.sv:551-557,591-613`；
- multiply/scale/limits：
  `../v0.94/rtl/custom_register_bank.sv:1926-1979`；
- divider/slew：
  `custom_register_bank.sv:1980-2036`；
- pipeline latency 当前为 8 clocks：
  `../version/STATUS.md:27-37`。

`[INFERENCE]` 真实有效 plant 是
`PZT plant in parallel with D2-controlled current closed loop`，不是单独 PZT。
所以离线 plant test 只能证明数字方向/边界，不证明真实稳定性。

## 6. lock 判断分层

必须分开显示：

1. `MODE=P_LOCK`：模式切换完成；
2. `ACQUIRING`：Kp ramp/supervisor 观察中；
3. `P_LOCKED`：FPGA mean/abs windows 达标；
4. 谱峰没有明显偏移：用户光谱证据；
5. P-only 收敛：error 相对 baseline 改善且无 saturation；
6. sustained lock：规定时间持续；
7. frequency stability improvement：需独立频率/PSD/Allan 类测量，当前不做。

FPGA `P_LOCKED` 只代表第 3 项，不自动升级到 4-7。

## 7. 最小显示字段

当前 L1 最小页面应显示：

- acquisition state、event type、generation、timestamp；
- selected OUT2、validated/captured actual OUT2、delta；
- error setpoint、raw error、lock_error；
- selected/actual scan direction 与 ERROR crossing direction；
- `kp_requested`、`kp_effective`；
- correction、absolute output、slew/update divider；
- saturation、supervisor mean/abs/counters、fault/reject reason；
- elapsed time in ACQUIRING/P_LOCKED；
- OUT2 到 correction/absolute limit 的 margin/trend；
- D2-125 state confirmation（明确标记 user-confirmed 或 UNKNOWN）。

## 8. 已实现 / 需调整 / 真正缺失

### 已实现，无需重复开发

- aligned capture；
- click/zero-crossing interpolation；
- independent directions；
- shadow/active target；
- VALIDATE/ACTIVE；
- realtime crossing；
- actual OUT2 bias；
- Kp ramp、servo divider、slew；
- correction/absolute limits、saturation；
- supervisor、event timestamp、fault/readback；
- GUI 主要 diagnostics。

### 最小调整

- 把 GUI 中旧 SIMPLE/LOCK HERE/APPLY P 文案统一为 L1；
- 把 PD feature selection 与 engineer direct ERROR selection 明确区分；
- VALIDATE comparison 设为 ACTIVE 的强制前置；
- 增加 D2 人工确认 block，并纠正“D2 Error Input 已接 FPGA error”的误导文案；
- 统一 state 的单一 owner，逐步减少 GUI flag 副本。

### 真正缺失

- `scan_generation` 的统一创建、持久与自动 invalidation；
- D2 external-controller state model / user confirmation；
- 混合 plant 的最小测量记录：polarity、bandwidth、DC/integrator、tuning signs；
- 完整 Timing Gate（当前仍有 unconstrained/no-delay/no-clock）；
- 真实硬件 VALIDATE、ACTIVE、PZT bumpless、P-only convergence、sustained lock。

### 当前不应加入

- PI/Ki、自动重锁、AI；
- Linien robust correlation gateware；
- PyRPL IQ/PID/lockbox framework；
- 双执行器自动协调；
- board daemon / RPC 大迁移；
- FPGABuilder build migration。

## 10. 验收条件

- full Timing Gate：WNS/TNS/WHS/THS 通过且 unconstrained paths=0；
- 用户确认接线与 D2 状态；
- 10 次 aligned capture 可重复，rising/falling 分开；
- VALIDATE generation/directions/guard/crossing coherent；
- ACTIVE 捕获 actual OUT2，Kp=0 数字和模拟 jump 可接受；
- 用户另行批准最小非零 Kp；
- error 改善、无 saturation、OUT2 不向 limit 漂移、谱峰无明显偏移；
- sustained duration 达 Gate 要求；
- 任一异常可 SAFE。
