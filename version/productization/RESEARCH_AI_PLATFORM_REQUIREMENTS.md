# RESEARCH_AI_PLATFORM_REQUIREMENTS

## 1. 第一版产品边界

第一版只做本地工具，不做云端 SaaS，不做 API 商城，不做论文代写，不做社区，不做流量节点。

目标用户：

```text
正在做硬件、控制、嵌入式、光电实验的工科研究生。
```

核心价值：

```text
把“AI 帮我推进项目”变成“AI 按阶段、权限、证据推进项目”。
```

## 2. 六个功能

| 功能 | 作用 | Red Pitaya 项目示例 | 第一版输入 | 第一版输出 |
|---|---|---|---|---|
| 项目状态页 | 显示当前阶段、已完成、未完成、风险、下一步 | v2A 初次实现完成，v2a-2 等待 Claude Code 审查 | `STATUS.md` 和阶段文档 | 一个可读状态页面 |
| 验证矩阵 | 区分设计、RTL、仿真、综合、上板、实验、论文证据 | PI core 仿真通过，但主工程未集成 | 模块列表和阶段记录 | 矩阵表格 |
| GPT 上下文包生成器 | 给 GPT 足够上下文做判断 | v2B 前五个物理问题 | 当前状态、相关文件、结果、问题 | GPT review package |
| Codex 任务生成器 | 约束 Codex 修改范围和验收标准 | 只允许改某两个文件，不运行 Vivado | 目标、允许文件、禁止项、测试 | Codex task prompt |
| 实验记录 | 固化 bitstream、接线、波形、参数和结论 | OUT2 只接示波器空载测试 | 日期、版本、接线、示波器现象 | 实验日志 Markdown |
| 周报生成 | 把碎片工作转成导师可读周报 | 本周 v2A 文档整理和 XSim 记录 | 本周完成/失败/状态/计划 | 周报 Markdown |

## 3. 明确不做

| 不做内容 | 原因 |
|---|---|
| API 商城 | 第一版价值在本地流程和模板，不在平台生态 |
| 论文代写 | 产品定位是证据管理和任务协作，不替代学术写作责任 |
| 社区 | 早期先验证单人/小组工作流 |
| 云端 SaaS | 工程项目常含未发表数据和实验室路径，先本地优先 |
| 自动修改 RTL | 第一版只生成任务和记录，不直接越权改代码 |
| 自动上板 | 涉及真实设备安全，必须保留人工确认 |

## 4. 数据对象

| 对象 | 字段示例 |
|---|---|
| ProjectState | 当前阶段、已完成事项、未完成事项、风险、下一步 |
| VerificationItem | 模块、设计状态、RTL 状态、仿真状态、综合状态、上板状态、实验状态、论文证据状态 |
| ReviewPackage | 项目背景、当前阶段、相关文件、Codex 结果、实验结果、需要 GPT 判断的问题 |
| CodexTask | 任务目标、上下文、允许修改、禁止修改、测试、验收、返回格式 |
| ExperimentLog | 日期、版本、bitstream、接线、输入、输出、参数、示波器现象、数据路径、结论 |
| WeeklyReport | 本周完成、本周失败、当前状态、下周计划、导师问题 |

- [ ] 周报生成页。

## 6. 验收标准

- [ ] 能用 Red Pitaya FPGA 激光稳频项目作为默认案例。
- [ ] 能生成不越权的 Codex 任务。
- [ ] 能清楚显示“仿真通过但还不能上板”的状态差异。
- [ ] 能导出 Markdown。
- [ ] 不需要联网即可使用。
- [ ] 不包含真实完整 RTL 和未发表原始数据。
