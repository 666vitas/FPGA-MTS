# CASE_STUDY_DRAFT

## 1. 案例定位

本案例以 Red Pitaya FPGA 激光稳频项目为样例，展示如何把一个容易失控的科研工程项目，整理成“阶段清楚、证据清楚、AI 分工清楚”的项目管理模板。

案例主题：

```text
用 Red Pitaya FPGA 逐步替代 D2-125 的基础 servo 功能，并为后续 AI 自动识峰、自动重锁和参数优化建立证据链。
```

## 2. 原始科研痛点

| 痛点 | 在本项目中的表现 | 如果不管理会怎样 |
|---|---|---|
| 目标漂移 | 一会儿想做 mixer，一会儿想做 PID，一会儿又想做 CNN | 每个方向都动一点，但没有一个阶段能闭合 |
| 代码、仿真、上板混在一起 | 独立 XSim 通过后，容易误以为可以直接接激光 | 可能跳过 Vivado、示波器和安全限幅检查 |
| AI 协作反复循环 | GPT、Codex、Claude Code 可能反复审查同一段 RTL | 时间花在重复审查上，而不是推进下一个物理阶段 |
| 实验现象记录不足 | 示波器波形、接线、参数、bitstream 来源没有统一格式 | 后续无法复现实验，也无法写论文证据 |
| 论文目标与工程步骤脱节 | AI 自动稳频是论文愿景，但当前 v2 只是 PI 核心 | 容易过早做 AI，忽略 FPGA 内环可靠性 |

## 3. 用 v1/v2/v3/v4 管理项目

| 阶段 | 当前项目含义 | 主要证据 | 不能提前声称 |
|---|---|---|---|
| v1 | FPGA 数字解调，生成 error-like signal，并由 OUT1 给 D2-125 使用 | mixer、LPF、真实链路波形、D2-125 可响应 | 不能说 FPGA 已替代 D2-125 |
| v2 | FPGA PI/servo 基础，逐步从独立 PI 核心走到 OUT2 低增益闭环 | v2A XSim、v2B 集成、v2C Vivado、v2D-v2F 实验 | 不能把 v2a-1/v2a-2 当完整系统版本 |
| v3 | scan/lock control 和自动重锁 FSM | 状态机仿真、锁定/失锁/重扫实验记录 | 不能说 AI 已经接管系统 |
| v4 | 数据集、benchmark、相位/IQ 优化等评估体系 | 数据集、指标表、跨工况对比 | 不能只展示最好的一次波形 |
| v5 | AI 慢速外环，如 CNN 识峰、参数建议、重锁策略 | 模型评估、误识别风险、与基线方法对比 | 不能让 AI 直接进入最快实时内环 |

## 4. GPT 与 Codex 如何协作

| 角色 | 在本项目中负责什么 | 不负责什么 |
|---|---|---|
| GPT | 定义阶段目标、判断物理风险、解释实验现象、决定是否进入下一阶段 | 不反复逐行审查已经由 Claude Code 审查过的同一版 RTL |
| Codex | 修改授权文件、编写 testbench、运行授权仿真、更新 version 记录、生成报告 | 不擅自上板、不擅自运行 Vivado、不擅自扩大范围 |
| Claude Code | 对本阶段代码做一次集中静态审查，给出 PASS/PASS WITH NOTES/FAIL | 不无限增加测试，不把未来优化当当前阻塞 |
| 用户 | 接线、观察示波器、保存数据、确认物理设备状态 | 不需要手工维护复杂版本证据链 |

### 可执行协作循环

- GPT 给出当前阶段的最小任务和通过标准。
- Codex 只在授权范围内修改文件并生成证据。
- Claude Code 对代码做一次集中审查。
- Codex 完成一次集中修正和回归。
- 若回归通过，则关闭该子阶段，进入下一个阶段。

## 5. 验证矩阵的价值

本项目把“完成”拆成多个证据层：

| 证据层 | 问的问题 | 本项目例子 |
|---|---|---|
| 设计状态 | 这个模块应该做什么 | v2A 是独立 PI 核心，v2B 才是主工程集成 |
| RTL 状态 | 代码是否写入指定文件 | `pi_controller.sv` 是否包含 I + anti-windup |
| 仿真状态 | testbench 是否通过 | XSim 165 tests / 165 PASS / 0 FAIL |
| 综合状态 | Vivado 能否编译完整工程 | v2C 才检查 synthesis/implementation |
| 上板状态 | bitstream 是否在 Red Pitaya 上运行 | v2D OUT2 只接示波器 |
| 真实实验状态 | 激光链路是否按物理预期工作 | v2F 低增益闭环替代 D2-125 |
| 论文证据状态 | 结果是否能支撑论文叙事 | v4 benchmark、v5 AI 外环对比 |

这能避免一句“已经完成”掩盖多个没有完成的层级。

## 6. 可迁移到其他工科研究生项目

| 可迁移对象 | 类似本项目的内容 | 模板化做法 |
|---|---|---|
| 嵌入式控制 | FPGA/MCU 控制器、传感器、执行器 | 阶段图 + 验证矩阵 + 实验日志 |
| 电机控制 | 位置/速度/电流环 | 仿真、空载、负载、闭环分层 |
| 光电实验 | 光路、探测器、锁相、反馈 | 接线表、示波器记录、参数表 |
| 机器人实验 | 感知、控制、执行机构 | 模块状态矩阵和真实场景测试 |
| AI+硬件项目 | AI 外环 + 实时硬件内环 | AI 不直接进入安全关键实时环路 |
