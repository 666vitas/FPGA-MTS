# 错误排查清单

## 0. 本文件作用

本文件用于出错时快速定位问题。

大白话：不要一出错就重写代码。先判断是仿真错、集成错、Vivado 错、还是实验接线错。

## 1. 我需要理解什么

错误大致分四类：

| 类型 | 例子 |
|---|---|
| 代码错误 | 语法、位宽、signed、reset |
| 仿真错误 | testbench 期望不对、时钟没等够 |
| 集成错误 | ADC/DAC 接错、OUT1/OUT2 接反 |
| 实验错误 | 信号太大、线接错、示波器触发不对 |

## 2. 我需要操作什么

按顺序排查：

1. 先看 testbench 是否通过。
2. 再看 Vivado 是否综合通过。
3. 再看 bitstream 是否对应当前版本。
4. 再看示波器是否直接量到输入信号。
5. 再看 `OUT1` 是否有波形。
6. 最后才怀疑复杂算法。

## 3. 我需要发给 GPT 什么

发：

```text
1. 当前版本名
2. 现象
3. 仿真是否通过
4. Vivado 报错
5. 示波器截图
6. 接线图
7. 输入信号频率/Vpp/offset
```

## 4. Codex 应该生成什么

Codex 应该生成：

- 针对错误的 `CORRECTION_*.md`；
- 修复 diff；
- 更新 REPORT；
- 必要时更新 BOARD_TEST。

## 5. 成功标准是什么

排查成功标准：

- 找到具体原因；
- 有可复现步骤；
- 有修复记录；
- 修复后 testbench 通过；
- 上板测试恢复到已知安全状态。

## 6. 常见错误表

| 现象 | 可能原因 | 先查 |
|---|---|---|
| `xvlog` 失败 | 语法错 | 报错行 |
| `xelab` 失败 | 模块缺失或端口不匹配 | 文件列表和端口名 |
| 仿真 `$fatal` | 输出不符合预期 | reset 和时序 |
| OUT1 没波形 | top 未接入、bitstream 错、reset 未释放 | integration plan |
| OUT1 削顶 | 输入过大或输出缩放错 | 输入 Vpp 和限幅 |
| OUT2 有波形 | DAC A/B 接反 | 示波器双通道 |
| IN2 没 REF | REF 没接到 IN2 或幅度太小 | 示波器直接量 REF |

## 7. 我现在只需要记住什么

每次失败都先回到最小版本：

```text
v1a -> v1b -> v1c
```

不要在基础通路没确认前调复杂算法。
